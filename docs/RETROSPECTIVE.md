## 팀 회고

### 좋은 점

1. **EDA에서 전략을 끌어냈다.** 질문의 약 70%가 글자 읽기 문제이고, 질문은 짧은데 이미지 짧은 변이 720px 안팎이라는 사실에서 "병목은 OCR과 해상도"라고 판단했다. 그래서 대형 VLM과 최대 896px 입력을 택했다. 같은 질문 문장이 최대 62번 반복된다는 발견은 질문 문장 단위 Group split으로, dev 투표 동률 465건은 "3표 합의 2,026문항만 사용" 규칙으로 이어졌다. 결정마다 근거가 된 데이터가 있었다.
2. **작게 비교하고 크게 확장했다.** 7B·8B 모델과 약 1,700장으로 방향을 정한 뒤 96GB GPU에서 27B로 넘어갔다. 비싼 GPU 시간을 방향이 정해진 실험에만 썼다.
3. **노이즈와 개선을 구분하는 기준을 코드로 고정했다.** 675문항 검증셋에서 2문항은 0.3%p다. "후보가 2문항 이상 좋을 때만 채택" 규칙을 노트북에 넣어, 감으로 고르는 일을 줄였다.
4. **계열이 다른 모델을 확률로 합쳤다.** Qwen과 Gemma의 test 예측 일치율은 94.18%였고, 두 모델이 갈린 391문항의 결론을 세 번째 모델의 확률이 정했다. 그 결과 Public 순위(126위)보다 Private 순위(88위)가 38계단 높았다. 결과 하나로 단정할 수는 없지만, Public 점수 하나만 쫓지 않고 서로 다른 모델을 섞은 선택이 나머지 50% test에서도 통했다는 신호로 본다.
5. **결과를 재현할 수 있게 남겼다.** 모든 모델의 a/b/c/d 확률을 CSV로 저장해, 스크립트 한 줄로 최종 제출 파일을 바이트 단위까지 다시 만들 수 있다. 실험 설정과 로그는 W&B와 저장소에 남겼다.
6. **투트랙으로 일을 나눴다.** 기본 train 학습(W&B로 실시간 공유)과 증강·외부 데이터·프롬프트·앙상블 실험을 병행해 다섯 명이 서로를 기다리지 않고 움직였다.

### 아쉬운 점

1. **커리큘럼을 끝까지 돌리지 못했다.** Gemma4-31B는 Stage 2의 43%에서 멈췄고 Qwen3.5-27B는 사실상 학습 없이 쓰였다. 대형 모델에서 Stage 3(외부 데이터)의 효과는 끝내 확인하지 못했다.
2. **한 번에 여러 조건을 바꿨다.** 27B 개선 설정에서 학습률·rank·batch·LoRA 대상·epoch·해상도를 한꺼번에 바꿔 항목별 기여도를 모른다. 전체 데이터 재학습이 −0.00089로 떨어졌을 때도 검증셋 제거, LoRA 재초기화, 샘플 순서가 동시에 바뀌어 원인을 가리지 못했다.
3. **앙상블 가중치를 Public 점수에 기대어 정했다.** 정답이 있는 검증셋에서 모든 후보 모델의 확률을 모으지 않았기 때문이다. Public 리더보드에 과적합할 위험을 안고 있었다.
4. **검증셋이 작고 한 번만 나눴다.** 675문항 단일 분할에서는 판단 하나하나가 2~3문항에 흔들렸다.
5. **선택지 편향을 점검하지 못했다.** 정답 선택지가 오답보다 평균 1자 길다(9.68자 대 8.61자)는 것을 알고도, 모델이 이 편향에 기대는지 확인하지 않았다.

### 개선점

1. 대회 초반에 대회 train에서 **고정 검증셋**을 만들고, 모든 모델과 모든 Stage를 같은 셋으로 평가한다.
2. 모든 후보 모델의 **out-of-fold 확률**을 저장해 앙상블 가중치와 temperature를 검증셋에서 고른다. Public 점수는 마지막 확인에만 쓴다.
3. **한 번에 한 조건만** 바꾸는 ablation을 실험 규칙으로 정하고, W&B 기록에 "바꾼 조건"을 필수 항목으로 둔다.
4. 이미지 없이 선택지만 보는 **text-only 기준선**으로 편향을 점검하고, 확신이 낮은 문항(앙상블 margin 0.2 미만 171문항)에 TTA를 적용한다.
5. 검증 신뢰도를 높이기 위해 **k-fold 교차검증**을 쓴다.

### 배운 점

1. **검증 상승과 제출 상승은 다르다.** 증강 80% 후보는 검증에서 2문항 올랐지만 Public 점수는 같았다. Public도 test의 약 50%(약 3,357문항)라서, 최종 앙상블의 이득 +0.00119도 약 4문항이다. 숫자를 문항 수로 바꿔 보면 무엇이 노이즈인지 보인다.
2. **이 과제에서는 해상도와 모델 용량이 결정적이었다.** Qwen3.8-27B는 미세조정 전에도 검증 94.37%였고, Stage 2를 절반도 못 마친 31B가 세 Stage를 모두 마친 4B보다 Public에서 0.108 높았다.
3. **앙상블의 힘은 다양성에서 나온다.** Public 점수가 0.95918로 같은 두 모델(증강 70%·80%)도 test 답이 48문항 달랐다. 계열이 다른 모델일수록 오답을 서로 덮을 여지가 크다.
4. **검증할 수 없는 방법은 채택하지 않는다.** 답만 모아 LLM에게 재판정시키는 방식은 그럴듯했지만 정답 없이 효과를 확인할 수 없어 버렸다.
5. **생성 대신 토큰 확률을 읽으면 얻는 것이 많다.** 형식 오류가 사라지고, 문항당 0.29초로 빨라지고, 그 확률이 그대로 앙상블 입력이 된다.

## 개인 회고 — 김순하

> 팀장 · 3-Stage 커리큘럼 QLoRA 설계·학습 · 확률 Soft Voting 앙상블 · 외부 데이터 확보(색상·개수·영어)

### 좋은 점

1. **중단을 전제로 설계한 덕분에 팀 최고 단일 모델을 건졌다.** 커리큘럼 노트북에 100 update마다 adapter, optimizer, scheduler, RNG 상태, 학습 데이터 fingerprint를 임시 폴더에 쓴 뒤 이름을 바꿔 저장하는 재개 체크포인트를 넣었다. 마감 때문에 Gemma4-31B의 Stage 2를 3,485 / 8,104 update에서 멈춰야 했지만, 그 시점의 체크포인트가 팀 단일 최고 점수(Public 0.96008)를 냈고 최종 앙상블의 한 축이 됐다.
2. **앙상블을 검증할 수 있는 방식으로 바꿨다.** 제출 CSV 3개가 갈린 286문항을 LLM에게 재판정시키는 방식은 정답 없이 효과를 확인할 수 없었다. 그래서 커리큘럼 노트북 마지막에 test 6,714문항의 a/b/c/d 확률을 뽑는 셀을 넣고, 확률을 가중 평균하는 방식으로 바꿨다. 결과는 Public 0.96127, Private 0.96723(88위)이었다.
3. **변형을 많이 만들되 근거 없이 바꾸지 않았다.** 단일 점수 기반 가중치 조정 4가지, temperature 보정·다수결·상위 2모델 합의 보호·확신도 게이팅 등 5가지를 만들었다. 모두 최종 top3와 31~72문항(0.5~1.1%)만 달라 우열을 가릴 근거가 부족했기 때문에, 리더보드에서 확인된 top3를 유지했다.
4. **외부 데이터를 바로 학습에 쓸 수 있는 형태로 만들었다.** CLEVR 색상·개수 2,000문항은 "색상/개수 × 정답 위치" 8개 조합을 250개씩 맞췄고, ST-VQA 영어 3,000문항은 26,074문항 후보에서 골라 원문 정답과 비슷한 형태의 오답을 생성해 4지선다로 바꿨다(정답 a~d 각 750개). 시드 고정, 동일 픽셀 중복 검사, 오답 생성 기록, 출처·주의사항 문서까지 남겼다.
5. **서로 다른 데이터 세 종류를 누수 없이 합쳤다.** 대회 CSV, 증강 CSV, Excel 메타데이터를 공통 8열로 바꾸고, 증강본은 원본 id 기준으로 묶어 같은 이미지의 변형이 train과 valid로 갈라지지 않게 했다. 긴 샘플에서 정답 토큰이 잘리면 길이를 늘려 다시 인코딩하는 처리도 넣었다.

### 아쉬운 점

1. **직접 모은 외부 데이터의 효과를 끝내 확인하지 못했다.** Stage 3는 대형 모델에서 사실상 실행되지 못했다(Qwen3.5-27B에서 2 update). 소형 모델은 Stage 3 검증이 85~94%였지만, 이는 외부 데이터에서 잰 값이라 test 성능을 말해 주지 않는다. 데이터를 모으고 다듬는 데 시간을 쓰면서 효과를 측정할 경로는 늦게 설계했다.
2. **학습 시간 예산을 먼저 세우지 않았다.** Stage 2만 64,829행(8,104 update)이었다. 31B·27B로 세 Stage를 마감 안에 마치기 어렵다는 것은 학습 전에 계산할 수 있었다. Stage 2를 줄이거나 Stage 3를 작게 먼저 검증하는 선택지가 있었다.
3. **Stage마다 검증셋이 달랐다.** 각 Stage 데이터에서 뽑은 검증셋으로 평가하다 보니, Qwen3.5-4B는 Stage 3 검증이 93.75%인데 Public은 0.85224였다. 대회 데이터에서 만든 공통 검증셋으로 모든 Stage를 평가했어야 Stage마다 무엇이 좋아졌는지 비교할 수 있었다.
4. **앙상블 가중치를 Public 점수에 기대어 정했다.** out-of-fold 확률을 모으지 않아서 정답이 있는 데이터로 가중치를 고를 수 없었다. Private 순위가 올랐지만 그것이 운이 아니었다고 보여줄 근거는 없다.
5. **"한 번에 한 조건" 원칙을 팀 규칙으로 만들지 못했다.** 팀장으로서 실험 기록에 바꾼 조건을 남기는 규칙을 초반에 정했다면, 전체 재학습이 떨어진 원인 같은 질문에 답할 수 있었을 것이다.

### 개선점

1. 학습 전에 Stage별 update 수 × update당 시간으로 **완주 가능 여부를 계산**하고, 어려우면 데이터를 줄이거나 순서를 바꾼다.
2. 외부 데이터는 **작은 모델과 공통 검증셋으로 "넣었을 때/뺐을 때"를 먼저 비교**한 뒤 대형 모델에 넣는다.
3. 커리큘럼의 모든 Stage를 **대회 데이터 기반 공통 검증셋**으로 평가해 Stage 전후 변화를 같은 잣대로 본다.
4. 앙상블 후보마다 **out-of-fold 확률**을 남겨 가중치를 검증셋에서 고르고, Public은 확인용으로만 쓴다.
5. 팀 실험 기록에 **"바꾼 조건" 칸을 필수로** 두고, 실험 계획을 세울 때 무엇을 비교하려는지 먼저 적는다.

### 배운 점

1. **긴 학습은 언제든 끊긴다는 전제로 설계해야 한다.** 재개 체크포인트가 없었다면 Gemma4-31B의 0.96008도, 최종 앙상블도 없었다.
2. **데이터의 가치는 측정할 경로가 있어야 생긴다.** 잘 모으고 다듬은 데이터라도 효과를 재지 못하면 성능에 기여했다고 말할 수 없다.
3. **앙상블은 정답 없이도 검증할 수 있는 형태여야 한다.** 확률 기반 결합은 재현하고 분석할 수 있었고, 답만 모으는 방식은 근거가 약했다.
4. **차이를 문항 수로 바꿔 보는 습관이 판단을 지켜 준다.** 0.3%p는 2문항, 앙상블 이득 +0.00119는 약 4문항이었다.
5. **모델 용량이 학습 완주보다 중요했다.** 같은 커리큘럼에서 절반만 학습한 31B가 끝까지 학습한 4B보다 크게 앞섰다. 다음에는 큰 모델을 먼저 확보하고, 남는 시간에 학습을 늘리는 순서로 계획하겠다.
